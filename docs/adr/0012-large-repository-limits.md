# ADR-0012：大仓库限流与有界展开

- 状态：Accepted（2026-10-18，迁移自现有实现）
- 相关：`src/host/core.ts`、`src/host/types.ts`、`src/client/virtual-list.ts`、issue #16、#33

## Context

两个操作在正常仓库上没问题，在大仓库上会失控：

- **逐文件统计**：为了给出每个变更文件的 `+/-`，host 对每个文件跑一次 `git diff --numstat`。一个有几千个未跟踪文件的仓库会让每一轮轮询刷出几百个 git 进程。
- **「展开全部」**：早期实现让 host 用 `-U100000` 把整个文件吐成一个 hunk，视图再全量渲染并逐格重新做语法高亮。实测 547 行文件：展开耗时 430ms（其中 367ms 主线程长任务），DOM 节点 8456。

两者都是「用户没要求那么多，但我们给了」——代价是进程数、内存与主线程阻塞。

## Decision

- **逐文件 fan-out 有上限**：`STATS_FANOUT_LIMIT`（200）与 `UNTRACKED_NUMSTAT_LIMIT`（32，未跟踪侧更低，因为每个都要额外 spawn）。超限**降级统计**（`stats.partial`）并在 UI 提示，而不是每轮轮询刷出几百个 git 进程。
- **「展开全部」上下文有界**：`DIFF_EXPAND_CONTEXT`（2000 行），够不到的部分继续以按需展开的 gap 呈现。**不要放大到整文件**。
- **长列表虚拟化**：变更列表、源码视图、DiffView 用 `virtual-list.ts` + `use-viewport.ts`，只挂载视口（加 overscan）内的行；查找跳到窗口外命中时**窗口吸附到命中邻域**，不挂载中间的连续区间。
- **逐行高亮缓存**（`highlight-cache.ts`），按行文本复用。

## Consequences

- 同一份 547 行文件：展开 430ms → **78–96ms**，无长任务；DOM 节点 8456 → **429**。
- 代价：虚拟化要求行高可预测——固定行高让窗口数学精确，换行导致的行高变化靠挂载行实测回填。
- 降级必须**可见**（`stats.partial` + 提示条），否则用户会把「简化后的统计」当成完整数据，这直接引出 ADR-0013。
