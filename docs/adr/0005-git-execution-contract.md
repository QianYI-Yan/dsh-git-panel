# ADR-0005：git 执行契约：argv、无 shell、锁仓库根、有界输出

- 状态：Accepted（2026-10-18，迁移自现有实现）
- 相关：`src/host/git.ts`、`src/host/core.ts`

## Context

插件的核心动作是替用户跑 git。这里有两个独立的失败模式：

- **注入**：把分支名、路径、标签名拼进 shell 字符串，等于把 RPC 输入直接交给 shell 解析。这些值全部来自界面，而界面上的值又来自仓库内容（分支名可以是攻击者可控的字符串）。
- **挂死**：网络命令（fetch / pull / push）在需要凭据或主机密钥确认时会阻塞等待终端输入。DSH 是常驻服务，一条挂住的 git 会让轮询堆积。

还有第三个隐患：进程的工作目录。仓库根不是「当前目录」——它要经过 realpath 解析（软链、大小写、`..`），否则同一次会话里的两条命令可能落在不同的树里。

## Decision

- 所有 git 命令经宿主 `subprocess` 服务执行，**argv 数组**传递，禁止拼接 shell 字符串；`shell: true` 在插件里不存在。
- **cwd 锁仓库根**：`core.ts` 用 realpath 解析出仓库根，每条命令都以它为 cwd；非 Git 目录回退到 cwd 作为浏览根。
- 每条命令带**超时与输出上限**，超限即截断并在结果里标记（见 ADR-0013），不把无界输出读进内存。
- 每条命令注入 `GIT_TERMINAL_PROMPT=0`（以及清空的 askpass 环境），让需要交互的命令**快速失败**成 `auth-failed`，而不是挂到超时。
- 写操作不继承调用方的环境变量：走 scrubbed env，避免把宿主的凭据相关变量意外带进子进程。

## Consequences

- 分支名里的 `;`、`$()`、换行都只是普通字符，注入面被 argv 传递消掉。
- `auth-failed` 是一个可预期的错误码而不是超时，UI 能给出「凭据不可用」的明确提示。
- 超时与输出上限意味着大仓库的极端输出会被截断——这必须显式暴露给用户（ADR-0013），否则会出现「看起来完整、其实少了一半」的 diff。
- 仓库根解析成 realpath 之后，同会话内所有命令面对同一棵树；代价是跨软链的仓库在 UI 上显示的是真实路径。
